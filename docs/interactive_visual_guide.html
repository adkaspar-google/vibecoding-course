Kief Morris: 'Why Loop' vs. 'How Loop'

Human-Owned 'Why Loop': Defines business outcomes, system architecture, program design (types/interfaces), and trade-offs.

Agent-Executed 'How Loop': Explores files, drafts code, runs tests, and self-repairs inside the harness.

Golden Rule: Never write 20 lines of prose in CLAUDE.md hoping the LLM obeys a rule if a 10-line Deterministic Linter or PreToolUse Hook can enforce it at 0 token cost!
⚠️ Learn About — Common Misconception vs. Reality
✕ Misconception
If a model advertises a 200k or 1M token context window, you get the same code quality at 160k tokens as at 30k tokens.
✓ Engineering Reality
Effective reasoning degrades sharply past ~40% context utilization ('The Dumb Zone'). High-leverage engineers use Frequent Intentional Compaction (`research.md` -> `plan.md` -> `/clear`) to stay under 35%.

⚠️ Learn About — Common Misconception vs. Reality
✕ Misconception
In an autonomous improvement loop, the agent should be allowed to edit both the solution code and the evaluation script.
✓ Engineering Reality
If the agent can edit the evaluator (`prepare.py` or test assertions), Goodhart's Law guarantees it will 'optimize' the metric by deleting assertions or shrinking validation data. The evaluation oracle must be strictly read-only.
💭 Stop & Think — Active Reflection
Why does Karpathy's `autoresearch` enforce a fixed 5-minute wall-clock training budget rather than a fixed number of training epochs?
Key Takeaway: Because a fixed epoch budget penalizes fast architectural innovations and rewards slow, compute-heavy models; a fixed 5-minute wall-clock budget forces the agent to optimize true hardware-aware Pareto efficiency on your exact GPU.
